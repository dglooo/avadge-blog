# Публикация статьи или новости в блог AVADGE

Статья и новость — одна сущность `BlogPost`, различаются только `category`:
`articles` (статья) или `news` (новость). Других значений нет. Рендерятся одним
шаблоном на `/blog/<category>/<slug>/`.

Четыре вещи, из-за которых чаще всего получается брак:

1. **Созданный пост невидим.** Он всегда создаётся черновиком (`published=false`)
   и на сайте не появляется. Публикует **пользователь**, отдельным словом, после
   того как посмотрит черновик. Сам не публикуй. Никогда.
2. **Обложка обязательна.** API технически позволяет пост без `cover_url`, но
   карточка поста в списках без обложки выглядит браком. Нет обложки — **спроси
   у пользователя ссылку или подбери из его материалов**, но не отправляй пост
   без неё.
3. **Внутри статьи должны быть фотографии.** Голая простыня текста — брак.
   Минимум **2 фото** в теле (`article-content-image`), распределённых по тексту,
   у каждого — осмысленный `alt` и, где уместно, подпись `figcaption`.
4. **Текст обязан пройти скилл `humanizer`** (если он доступен в системе) ПЕРЕД
   отправкой: убрать ИИ-штампы, канцелярит, «правило трёх», лишние тире. Статья
   должна читаться как написанная живым автором АВАДЖ, а не нейронкой.

## Ход работы

1. **Собери материал:** тема, факты, фотографии (ссылками), марка авто (если пост
   про конкретную марку — `mark` точным именем из каталога; общая новость — без марки).
   Чего не хватает — спроси, не выдумывай факты.
2. **Напиши текст** (структура ниже), объём статьи — от ~300 слов (тоньше — это
   «тонкая страница», SEO-брак; для коротких новостей допустимо меньше, но не
   меньше ~100).
3. **Прогони текст через скилл `humanizer`.** Результат — финальная редакция.
4. **Свёрстай в «наш формат»** (ровно семь блоков, класс обязателен у каждого —
   без класса блок ломает вёрстку и блок-редактор админки):
   - Абзац: `<p class="article-content-text">…</p>`
   - Заголовок: `<h2 class="article-content-heading">…</h2>` (h2–h5)
   - Цитата: `<blockquote class="article-content-quote">…</blockquote>`
   - Список: `<ul class="article-content-list"><li>…</li></ul>` (или `<ol>`)
   - Картинка: `<figure class="article-content-image article-content-image--centered">`
     `<img src="…" alt="…"><figcaption>…</figcaption></figure>`
   - Разделитель: `<hr class="article-content-divider">`
   - Таблица: `<table class="article-content-table">…</table>`
5. **Отправь** `create_post(title, content, category, cover_url, …)` — заполни
   `meta_title`/`meta_description` (до ~160 символов, с ключевой фразой).
   **Теги:** если пользователь их явно назвал — передай ровно их (строка через
   запятую). Если НЕ называл — **не передавай `tags` вообще**: сервер сам
   поставит единственный тег марки. Никогда не выдумывай набор тегов и не
   вешай весь справочник марок — это брак. `update_post(tags=…)` заменяет
   набор целиком.
6. **Проверь** возвращённый `snapshot` (или `get_post(id)`): контент цел, обложка
   встала, категория верная. Правки — `update_post` (пустая строка = «не менять»).
7. **Покажи пользователю ссылку/содержимое черновика** и жди его «публикуй» →
   `publish_post(id)`.

## Фотографии

| Что | Правило |
|---|---|
| Обложка | ОБЯЗАТЕЛЬНА. `cover_url` = прямая HTTPS-ссылка; Django скачает сам. Горизонтальная, без водяных знаков чужих сайтов. |
| Внутри текста | Минимум 2 `article-content-image`, равномерно по тексту (не подряд). Прямые HTTPS-ссылки в `src` — предпочтительно наши домены (avadge.com, s3.regru.cloud). |
| `alt` | Обязателен у каждой картинки, по-русски, описывает содержимое (SEO). |
| Локальные файлы | MCP принимает только URL. Файлы с диска → сперва загрузить через блок-редактор админки (`/blog/admin/block-editor/upload/`, нужна staff-сессия) или на S3, потом ссылку в контент. Нет возможности — попроси у пользователя ссылки. |

## Грабли

- **Таймаут `create_post` ≠ «пост не создан»:** обложка скачивается внутри запроса,
  Django мог успеть создать черновик. Не повторяй вслепую — черновик не виден на
  сайте, поищи в админке по заголовку.
- **Кириллический заголовок — ок:** slug генерируется транслитом и уникализируется
  сам, дубли заголовков не падают.
- `update_post` трактует пустую строку как «не менять» — очистить SEO-поле через
  MCP нельзя, только в админке.
- Тег с запятой внутри непередаваем (`tags` режется по запятым).
- Марка должна существовать в каталоге — несуществующая даст ошибку валидации.

## Чек-лист перед `create_post`

- [ ] Текст прошёл humanizer, факты — от пользователя, не выдуманы
- [ ] ≥300 слов (статья) / ≥100 (новость)
- [ ] `cover_url` заполнен
- [ ] ≥2 `article-content-image` в теле, у всех `alt`
- [ ] Каждый блок имеет свой `article-content-*` класс
- [ ] `category` = `articles` или `news`, `meta_title`/`meta_description` заполнены
- [ ] Теги: только от пользователя, иначе аргумент не передан (дефолт = тег марки)
- [ ] Помнишь: это черновик — публикация только по слову пользователя
